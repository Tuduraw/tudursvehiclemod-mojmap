# Readme_cfg.md - Config設定

対象ファイル:
- `config/tudursvehiclemod.json`(クライアント設定)
- `config/tudursvehiclemod-server.json`(サーバー設定)

いずれもJSON形式で、ファイルが存在しない場合は初回起動時にデフォルト値で自動生成されます。古いバージョンで作られたファイルに、その後追加された項目がない場合は、起動時にその項目が初期値で追記されます(すでに書かれている値はそのまま残ります。このバージョンが知らない項目も消さずに残します)。ゲーム内の設定画面から変更した場合は即座にファイルへ保存されるため、手動でファイルを編集する必要は基本的にありません。

## ゲーム内での開き方

いずれかの車両に搭乗した状態で「乗り物メニューを開く」キーを押し、乗り物メニュー内の「デバッグ」ボタンを押すと、デバッグメニューが開きます。そこに「設定」(クライアント設定)と「サーバー設定」への入り口があります。

「サーバー設定」は、自分がホストしているワールド(シングルプレイ、または自分が公開したLANゲーム)でのみ操作できます。リモートの専用サーバーの設定は、この画面から直接変更することはできません。

## 1. 反映タイミングについて

設定項目によって、変更がいつ反映されるかが異なります。

- **即時反映**: 毎フレーム/毎tick読み直される設定。ボタンを押した瞬間から効果が変わります。
- **リロード時に反映**: リソースリロード(デバッグメニューのリロードボタンで即座に実行可能)のタイミングで効果が変わる設定。テクスチャの読み込み処理に関わるものが該当します。
- **再起動が必要**: ゲームのそのセッション中、最初に一度だけ構築される仕組みに関わる設定。変更後、ゲームを再起動するまで見た目には反映されません。

以下の各項目でこの3種類のどれに該当するかを明記しています。

## 2. クライアント設定(`tudursvehiclemod.json`)

### 半透明処理(`translucencyMode`) - 再起動が必要

乗り物の透過部分(窓・光学系パーツ等)をどう描画するかの方式です。
デフォルトは`dither_texture`。

| 値 | 表示名 | 特徴 |
|---|---|---|
| `dither_shader` | ディザ (シェーダー) | このMOD独自のシェーダーでディザ処理。シェーダーパックとは併用できません(パックが独自の描画プログラムに置き換えてしまうため)。 |
| `dither_texture`(デフォルト) | ディザ (テクスチャ) | ディザパターンを読み込み時にテクスチャへ焼き込む方式。シェーダーパックと併用可能で、水面やエンティティとの前後関係も正しく処理されます。 |
| `translucent` | アルファブレンド | バニラの半透明パイプラインをそのまま使用する、素直なアルファブレンド。シェーダーパックと併用可能ですが、描画順に依存するため水面が透過部分の奥に隠れてしまう場合があります。 |

### サーチライト(`searchLightMode`) - 照明は即時反映、形状は再起動が必要な場合あり

サーチライトの照明方式と見た目の形状の両方を1つの設定で切り替えます。
デフォルトは`beam`。

| 値 | 表示名 | 特徴 |
|---|---|---|
| `beam`(デフォルト) | ビーム | 閉じた半透明の円錐(MCヘリ本来の形状)。エンティティのみを照らします。 |
| `dynamic_light` | ダイナミックライト(実験的) | 見た目はビームと同じですが、地形も実際に再照明されます(チャンクの再構築を伴う実験的機能)。 |
| `blades` | 光条 | ビームと同じ照明方式のまま、円周方向に伸びる数本の光条として描画。どの半透明処理設定でも正しく表示されます。 |
| `bands` | バンド | ビームと同じ照明方式のまま、長さ方向に並ぶ環状のリングとして描画。 |
| `dashes` | ダッシュ | 光条をさらに短い区間に区切った、破線状の表示。 |

### サーチライトの明るさ(`searchLightBrightness`) - 即時反映

- 範囲: 0 - 6(初期値: 3.0、0.5刻み。3.0を超えると1.0刻み)
- 点灯中のサーチライトがブロックやエンティティを照らす明るさの倍率です。各ライトに設定された強度を置き換えるのではなく、それを倍率で調整します。0にすると照明が無効になり、見た目のビームのみが残ります。

### ブロック描画の明るさ(`searchLightBlockBrightness`) - 即時反映

- 範囲: 0 - 3(初期値: 1.0、0.5刻み)
- サーチライトが地形を染める強さです。サーチライトの明るさ(エンティティ照明を制御)とは独立しています。0にすると地形への描画のみが無効になり、エンティティ照明はそのまま残ります。

### ブロック描画のサンプル数(`searchLightBlockOverlaySampleCount`) - 即時反映

- 範囲: 50 - 400(初期値: 200、50刻み)
- 地形のどこが照らされているかを判定するために、サーチライトが1tickあたりに発射するサンプル数です。ライトの形状や射程とは無関係の固定値です。少ないほど軽くなり、サンプルが粗いことで生じる隣接面のわずかな隙間は拡散処理が補完します。

### ブロック描画の更新間隔(`searchLightBlockOverlayIntervalTicks`) - 即時反映

- 範囲: 1 - 10 tick(初期値: 4)
- 地形への描画を完全に再計算する頻度です。サーチライトの処理の中で最も多くの一時メモリを消費する部分のため、値を大きくするとメモリの消費が比例して減ります。その代わり、素早く動くビームに対して描画の追従がわずかに遅れます。照明そのものは、この設定に関わらず常に毎tick更新されます。

### 円錐表示距離(`searchLightConeDisplayDistance`) - 即時反映

- 範囲: 0.1 - 1.0(初期値: 1.0、0.1刻み)
- 円錐/光条/バンド/ダッシュの見た目の形状が届く距離を、ライト本来の長さに対する割合で指定します。描画される範囲のみに影響し、照明やブロック描画の範囲は変わりません。

### チャンク再構築間隔(`searchLightChunkRebuildIntervalTicks`) - 即時反映

- 範囲: 1 - 40 tick(初期値: 10)
- サーチライトが「ダイナミックライト」の場合のみ使用されます。ビームの移動に応じて地形の再照明を要求する頻度です。小さいほど滑らかですが負荷が増えます。

### リング数の倍率(`searchLightRingCountMultiplier`) - 即時反映

- 設定画面では0.5・1.0・2.0・3.0の間を循環(初期値: 1.0)
- 光条/バンド/ダッシュのビームが長さ方向に生成するリング数の倍率です。サイズに応じた自動調整に加えて適用されます。上限は設けられていないため、画面上の循環範囲を超える値を使いたい場合はファイルを直接編集してください。

### ブレード数の倍率(`searchLightBladeCountMultiplier`) - 即時反映

- 設定画面では0.5・1.0・2.0・3.0の間を循環(初期値: 1.0)
- 光条/ダッシュのビームが円周方向に生成するブレード数の倍率です。リング数の倍率と同様、上限はなくファイルの直接編集で超過値を指定できます。

### ディザ拡大率(`translucencyDitherUpscale`) - リロード時に反映

- 取りうる値: 0.25 / 0.5 / 1 / 2 / 4 / 8(初期値: 4.0)
- ディザ処理前のテクスチャ拡大率です。1より大きいとメモリと引き換えに細かい模様になり、1より小さいと縮小してメモリを節約します。半透明処理が「ディザ (テクスチャ)」の場合のみ意味を持ちます。

### GPUテクスチャ圧縮 (BC1)(`translucencyDitherGpuCompression`) - リロード時に反映

- 初期値: `false`
- ディザ処理したテクスチャをBC1で保持し、VRAM使用量を1/8にします。アルファは正確に保たれますが、色の細部は近似になります。Minecraft本来のテクスチャAPIの外で動作するため、失敗時は自動的に従来方式へ戻ります。半透明処理が「ディザ (テクスチャ)」の場合のみ意味を持ちます。

### ディザ最大テクスチャ(`translucencyDitherMaxTextureSize`) - リロード時に反映

- 範囲: 512 - 8192 px(初期値: 2048、倍々で循環)
- 拡大後テクスチャのサイズ上限です。ディザ拡大率を制限します。半透明処理が「ディザ (テクスチャ)」の場合のみ意味を持ちます。

### 実験的な三角形描画(`experimentalTriangleRendering`) - 再起動が必要

- 初期値: `false`
- 三角形あたり4頂点ではなく3頂点で送信する実験的な描画方式です。半透明処理が「ディザ (シェーダー)」の場合のみ意味を持ちます。

### 描画距離に合わせる(`matchChunkViewDistanceForEntityRender`) - 即時反映

- 初期値: `true`
- このMODのエンティティ(車両・弾丸)に、短いエンティティ描画距離ではなくゲーム本来の描画距離(チャンク表示距離)を使用します。

### 描画カリングを無効化(`disableEntityRenderCulling`) - 即時反映

- 初期値: `true`
- このレンダラー独自の距離・視錐台判定を省略し、読み込まれている限り常に車両を描画します。

### 遠方の機体を描画(`renderFarVehicles`) - 即時反映

- 初期値: `false`
- LOD mod(Distant Horizonsなど)と併用するための設定です。描画距離より遠くの機体と、ミサイル・爆弾などのモデルで描画される弾を描画し、LOD modが描く遠景の地形の上にも機体が見えるようにします。
- サーバー(シングルプレイではそのワールド)の「遠方の機体の同期」(`farVehicleSyncEnabled`、下記)がオンの場合のみ機能します。
- 遠方の機体の可動部は、サーバーから送られた状態で描画されます。脚・ハッチ・キャノピー・ウェポンベイ・折りたたみ翼は開閉の状態、砲塔は向き(どちらも送信の間はなめらかに移行)、プロペラ・ローターは回転の速さ、破壊された機体は残骸として表示されます。車輪・履帯の回転、砲の反動、航跡、サーチライトの光、煙などは描画されません。光は屋外の明るさ固定です。
- 遠方の機体が描画距離内に入って通常の機体に切り替わるときは、遠方表示の状態(脚・ハッチの開閉、砲塔の向きなど)から続けて動きます。遠方の機体の描画を使っていない場合も、描画距離内に入ってきた機体の脚・ハッチなどは最初から現在の状態で表示されます(格納などの動作を最初からやり直しません)。
- 遠方の機体のエンジン音と武器の発射音も再生されます(サーバーから送られたエンジンの状態に合わせた音量・音程)。聞こえる範囲は近くの機体と同じで、エンジン音は`engine_sound_volume`、発射音は武器の`SoundVolume`に応じた距離までです。爆発音はゲーム本来の仕組みで鳴るため、この設定とは関係なく、近くでのみ聞こえます。
- 注意点:
  - 遠方の機体は遠景の地形に隠れず、山の向こうでも透けて見えることがあります。LOD modの地形は、ゲーム本来の奥行き情報に含まれないためです。
  - ゲーム本来の霧がかかっていると、描画距離より遠くの機体は霧で見えません。LOD mod側でバニラの霧を無効にしてください。
  - Distant Horizonsとの併用では機能しないことが報告されています(原因未特定。READMEの「既知の非互換性」を参照)。
  - この設定がオンの間は、ゲームの描画の奥行きの上限(通常は描画距離の4倍)を、下の描画距離まで延ばします。

### 遠方の機体の描画距離(`farVehicleRenderDistance`) - 即時反映

- 画面で選べる値: 512 / 1024 / 2048 / 4096(ブロック、初期値: 2048)
- 「遠方の機体を描画」がオンのとき、どこまで遠くの機体を描画するかです。サーバー側の上限(`farVehicleSyncMaxDistance`)がこれより短い場合は、そちらまでになります。

### 三人称HUD(`showHudInThirdPerson`) - 即時反映

- 初期値: `true`
- 三人称視点でも乗り物HUDを描画するかどうかです。一人称視点では、この設定に関わらず常に描画されます。

### 航空機カメラの最大距離(`maxAircraftCameraDistance`) - 即時反映

- 範囲: 20 - 160ブロック(初期値: 80、20刻み)
- 飛行中に三人称カメラをどこまでズームアウトできるかです。

## 3. サーバー設定(`tudursvehiclemod-server.json`)

「サーバー設定」画面の変更は再起動不要で即座に反映されます。

### 並列ヒット検出(`parallelHitDetectionAcrossVehicles`) - 即時反映

- 初期値: `false`
- このMOD独自のヒット検出処理を、各車両が個別のtick内でインライン実行する代わりに、全車両分をまとめて1tickにつき1回の並列処理としてバッチ実行します。ヒット検出が明らかにボトルネックとなっている、高ポリゴン車両が多いワールドでオンにしてください。

### 並列ヒット検出の最小車両数(`parallelHitDetectionMinimumVehicles`) - 即時反映

- 範囲: 1 - 20(初期値: 3)
- そのtickでヒット検出を必要とする車両が何台以上であれば、上記の並列処理を使う価値があるかを指定します。「並列ヒット検出」がオンの場合のみ意味を持ちます。

### 破壊された車両のデスポーン(`destroyedVehicleDespawnEnabled`) - 即時反映

- 初期値: `true`
- 破壊された車両が、残骸として永久にワールドに残り続ける代わりに、下記のタイマー経過後に自動的にデスポーンするようになります。正常に運転可能な車両には一切影響しません。

### 破壊された車両のデスポーンまでの時間(`destroyedVehicleDespawnSeconds`) - 即時反映

- 範囲: 30 - 1800秒(初期値: 300 = 5分)
- 破壊された車両がデスポーンするまでワールドに留まる時間です。「破壊された車両のデスポーン」がオンの場合のみ意味を持ちます。

### 弾丸チャンクロード上限(`projectileForcedChunkLimit`) - 即時反映

- 取りうる値: 無効(0) / 50 - 1000(初期値: 300)
- 飛翔中の弾丸がサーバー全体で強制ロードするチャンク数の合計上限を設定します。これにより、プレイヤーから離れた場所を飛ぶ弾丸でも着弾まで動作し続けます。上限を超える場合、召喚タイミングが最も古い弾丸から解除されます。無効(0)にすると、弾丸は一切チャンクを強制ロードしなくなります。CAS/Carrier機体や他の常時ロード機能には影響しません(それらは対応する武器・車両ファイル側で調整できます)。
- 弾の状態(爆発・信管・誘導など)はワールドに保存されません。サーバーを停止したとき(シングルプレイでワールドを閉じたときを含む)は飛翔中の弾の強制ロードが解除され、その弾は次にそのチャンクが読み込まれたときに(爆発せずに)消去されます。


### 自動操縦機の衝突回避(`autopilotCollisionAvoidance`) - 即時反映

- 初期値: `true`
- CAS・艦載機(Carrier)・編隊の僚機・ドローンなど、自動で飛んでいる航空機が、進路上にある他の機体(僚機・母艦・艦船・地上の車両など)をそのモデルを囲む直方体とみなし、約2秒(40tick)先までにその直方体(自機の大きさ+3ブロックの余裕を加えた範囲)に入りそうな場合、外側へ進路をずらします。真下に機体がある場合は下へは避けません(上へ避けます)。
- 母艦への着艦中・母艦からの発艦中は、その母艦は回避の対象外です。
- プレイヤーが操縦している機体、接地中の機体、破壊された機体には働きません。
- 回避は進路(速度)をずらすだけで、機首の向きは変えません。避けたあとは自動操縦が元の経路に戻します。
- 編隊の間隔や甲板上の駐機が密な場合、回避が互いに押し合うことがあります。その場合はオフにしてください。

### 遠方の機体の同期(`farVehicleSyncEnabled`) - 即時反映

- 初期値: `false`
- 「遠方の機体を描画」(クライアント設定)をオンにしたプレイヤーに、エンティティとして送られる範囲(サーバーの描画距離)より遠くにいる機体の位置・向き・動きを送ります。LOD modの遠景の上に機体が見えるようになります。
- 遠くの機体の位置が分かるようになるため、初期値はオフです。PvPのサーバーなどでは注意してください。
- 弾は、モデルで描画されるもの(`BulletModel`のある武器のミサイル・爆弾・砲弾など)だけを送ります。通常の弾丸は遠くでは見えないほど小さく、数も多いため対象外です。弾は動きが速く突然消えるため、機体より短い間隔(`farVehicleSyncProjectileIntervalTicks`、初期値4tick)で送ります。1人に送る最大数は`farVehicleSyncMaxProjectiles`(初期値64、0で送らない)です。どちらもファイルでのみ変更できます。着弾した弾は、次の送信までの間(初期値で最大4tick)そのまま進んで見えることがあります。
- 対象は、サーバーで読み込まれているチャンクにいる機体と弾です。強制ロードされたチャンク(飛行中の弾・CAS/艦載機・遠隔操縦の機体などが自動で行うもの、他のmodが`ChunkForceTracker`などで行うもの)にいる機体・弾も含みます。誰も近くにいない(チャンクローダーもない)場所の機体は、サーバー上に存在しないため見えません。
- 送る範囲は、プレイヤーの設定と下の上限の短いほうです。送る間隔(`farVehicleSyncIntervalTicks`、初期値10tick)と、1人に送る最大数(`farVehicleSyncMaxCount`、初期値64、近い順)は、ファイルでのみ変更できます。間隔の間は、クライアントが受け取った速度から位置を補って動かします。

### 遠方の機体の同期距離(`farVehicleSyncMaxDistance`) - 即時反映

- 画面で選べる値: 512 / 1024 / 2048 / 4096(ブロック、初期値: 2048)
- プレイヤー側の設定にかかわらず、どこまで遠くの機体を送るかの上限です。

### 車両の速度倍率(`vehicleSpeedMultiplier`) - 即時反映

- 画面で選べる値: x0.25 / x0.5 / x0.75 / x1 / x1.25 / x1.5 / x2 / x3 / x5 / x10(初期値: x1)。ファイルを直接編集すれば任意の値を設定できます(0.05未満は0.05として扱います)
- すべての車両の最高速度に掛ける倍率です。各車両の`max_speed`のほか、速度を直接指定する項目(可変翼を畳んだときの`SweepWingSpeed`、潜水艦の`dive_max_speed`、カタパルト発進の速度)にも掛かります。スロットルの段階・失速速度・自動操縦の巡航速度など、最高速度に対する割合で決まる速度は自動的に追従します。
- 加速・旋回など、速度以外の運動性能は変わりません。そのため、倍率を上げると最高速度に達するまでの時間は長くなります。
- 車両の動きはプレイヤーのクライアント側でも計算されるため、この設定は参加時と変更時にサーバーから各プレイヤーへ送られます。

### 車両の種類ごとの速度倍率(`vehicleSpeedMultiplierByType`) - 即時反映

- 画面で選べる値: 共通 / x0.25 〜 x10(初期値: 共通)。画面には航空機・VTOL機・ヘリコプター・車両・船・潜水艦の6種類が並びます
- 特定のエンティティタイプの車両にだけ使う速度倍率です。個別の値がある種類はその値を使い、ない種類(初期状態ではすべて)は上の共通の「車両の速度倍率」を使います。
- ファイルではエンティティタイプのIDをキーにして書きます。このMODの種類は`"aircraft"`のように名前だけでも書けます。アドオンの車両は、そのアドオンのID(例: `"mcheliaddon:mcheli_plane"`)で指定します。項目を消すと共通の設定に戻ります。

```json
"vehicleSpeedMultiplierByType": {
  "aircraft": 1.5,
  "tudursvehiclemod:ship": 2.0
}
```

### 武器ダメージ倍率(`weaponDamageMultiplier`) - 即時反映

- 画面で選べる値: x0 / x0.25 / x0.5 / x0.75 / x1 / x1.25 / x1.5 / x2 / x3 / x5 / x10(初期値: x1)。ファイルを直接編集すれば0以上の任意の値を設定できます
- このMODの武器の弾がエンティティや車両に命中したとき(直撃)のダメージに掛ける倍率です。各武器ファイルの`Power`はそのままに、サーバー全体で威力を調整できます。
- x0では命中してもダメージを与えません。生物は命中したときと同じようにノックバックだけを受けます(被弾時の赤い点滅や無敵時間はありません)。
- 爆発のダメージは下の「爆風倍率」で別に設定します。墜落・衝突・浸水のダメージには影響しません。

### 爆風倍率(`explosionBlastMultiplier`) - 即時反映

- 画面で選べる値: 武器ダメージ倍率と同じ(初期値: x1)
- このMODの武器の爆発と、車両が破壊されたときの爆発が、エンティティや車両に与えるダメージに掛ける倍率です。爆風の届く範囲、吹き飛ばしの強さ、爆発の見た目は変わりません。
- x0ではダメージを与えず、エンティティを吹き飛ばすだけになります。

### 爆発のブロック破壊倍率(`explosionBlockMultiplier`) - 即時反映

- 画面で選べる値: 武器ダメージ倍率と同じ(初期値: x1)
- このMODの武器の爆発と、車両が破壊されたときの爆発が、ブロックを壊す範囲(および火をつける範囲)に掛ける倍率です。爆風倍率とは独立しています。武器の爆発では`ExplosionBlock`(未指定なら`Explosion`)の値に、車両の爆発ではバニラの爆発の届く強さに掛かります。
- x0ではブロックを一切壊さず、火もつけません。
- もともとブロックを壊さない爆発(武器の`ExplosionBlock = 0`、燃料気化爆弾、ゲームルール`mobGriefing`がオフのときの車両の爆発など)は、倍率を上げても壊すようにはなりません。弾がガラスを割る・`Piercing`で貫通する処理は爆発ではないため、この倍率の対象外です。

## 4. 設定画面には出てこない項目

以下は設定ファイルには存在しますが、ゲーム内の設定画面には表示されていないため、変更するにはファイルを直接編集する必要があります。

### `searchLightBlockOverlayRange`(クライアント設定)

- 初期値: `50.0`(ブロック)
- サーチライトから何ブロックの範囲まで地形をその色で染めるかです。この距離に向かって効果が徐々に薄れていきます(唐突に途切れることはありません)。ライト自体の長さがこれより短い場合は、ライトの長さで打ち切られます。この項目はブロック数の3乗に比例して負荷が増えるため、この機能全体の中で最も負荷に影響する設定です。低スペック環境では下げてください。

### `worldDataCleanupChunksPerTick`(サーバー設定)

- 初期値: `-1`(件数上限なし)
- `/tvm clean -d`(ワールド上の全ての未読み込みチャンクを含めて車両を完全削除するコマンド)が、1tickあたりに調査するチャンク候補数の上限です。-1(デフォルト)では件数による上限を設けませんが、これは「1tickで処理が完結する」という意味ではありません。処理時間そのものは常に別途制限されており、進捗も定期的にログへ出力されます。正の値(例: 50)を設定すると、その時間制限に加えてチャンク数でも上限を設け、1tickあたりの負荷をより穏やかにする代わりに、処理全体の完了までの時間はさらに伸びます。


### `hitMeshBuildMaxConcurrent`(サーバー設定)

- 初期値: `-1`(上限なし)
- 当たり判定用メッシュ(機体モデルから作る命中判定のデータ)は、その機体がワールドに読み込まれた時点でバックグラウンドで作成されます(以前は最初に命中したときにサーバースレッドで作成していたため、高ポリゴンの機体では命中の瞬間に処理が止まることがありました)。この項目は、同時に作成する機体定義の数の上限です。-1では上限なし(CPUコア数に応じて並列に処理)、正の値(例: 1)ではその数までに制限し、優先度の低いスレッドで処理します。サーバーの負荷を抑えたい場合は小さい値にしてください。変更はサーバーの再起動後に反映されます。
- `/reload`を実行すると、メモリ上のモデルのキャッシュ(当たり判定用メッシュなど)は破棄され、OBJファイルが読み直されます。ローラー用のディスクキャッシュ(`.track-roller-bounds.txt`)はOBJの変更を検知しないため、モデルを編集した場合は手動で削除してください。

### `fireSupportDesignatorRange`(サーバー設定)

- 初期値: `512`
- 支援射撃指示器で目標を指示できる最大距離(ブロック)です。指示する地点は読み込み済みのチャンク内である必要があります。

### `fireSupportMaxDistance`(サーバー設定)

- 初期値: `4096`
- 支援射撃管制装置の画面で入力できる相対座標の上限(各軸、ブロック)です。

## 5. 強制ロードのリセット(`/tvm unloadchunks`)

設定項目ではありませんが、チャンクの強制ロードに関わるコマンドとしてここにまとめます。

- **権限**: OP(権限レベル2以上)
- **内容**: 全ディメンションの強制ロード中のチャンクから、このmodの機能が現在使っているものだけを残し、それ以外の強制ロードをすべて解除します。
  - 解除されたチャンクは、通常どおりプレイヤーの周囲だけが読み込まれるようになります。
  - 使用中のもの(飛行中のCAS/Carrier機や母艦、有効なDrone Center、Station、飛翔中の弾など)の強制ロードは維持されるため、実行しても動作は途切れません。実行後に始まる強制ロードも通常どおり機能します。
- **用途**: 以前のバージョンでは、機体・弾・Drone Center・Stationがなくなった後も強制ロードが解除されずに残ることがありました。強制ロードはワールドに保存されるため、再起動しても残ります。このコマンドで、こうした残留分をまとめて解除できます。
- **注意**: バニラの`/forceload`で手動で設定した強制ロードや、他のmodが設定した強制ロードも解除されます。必要なものは実行後に設定し直してください。
- **表示**: 解除したチャンク数と、使用中のため維持したチャンク数が、ディメンションごとに表示されます。
- **実行のタイミング**: ワールドの読み込み直後(サーバー起動から約10秒間)は実行できません。読み込まれた機体やDrone Centerなどが強制ロードを要求し直す前に実行すると、それらのチャンクまで残留分として解除してしまうためです。
- **ブロックを`/setblock`などで置き換えた場合**: Drone Center・Stationをプレイヤーが壊したときは、強制ロードの解除などの後始末が行われます。一方、`/setblock`(`destroy`指定なし)・`/fill`・`/clone`などで置き換えた場合は、バニラの仕様でこの後始末が行われません。このとき残った強制ロードは、このコマンドで解除できます。

## 6. 接触判定の表示(`/tvm debug contacts`)

- **権限**: OP(権限レベル2以上)
- **内容**: 機体の形状による接触判定(README「機体形状による接触判定」)で見つかった接触点を、パーティクルで表示します。実行するたびにON/OFFが切り替わります。表示は全プレイヤーに見えます
  - 赤: 機体同士の接触
  - 黄: 機体と生物(プレイヤー・mob)の接触
- **表示**: 実行時に、作成済みの形状格子の数・中身のある格子の数・使用メモリが表示されます
- **注意**: 表示中は読み込まれている全機体の接触を毎秒数回判定します。確認が終わったらOFFにしてください
